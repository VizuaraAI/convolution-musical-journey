What Gets Replaced

In a standard Transformer, every layer has two sub-blocks: one for cross-token mixing (Attention) and one for per-token processing (FFN). Mamba replaces both with a single, unified block.

Chapter 8 showed one token update. During training, we need the hidden state for every token in a long sequence. A plain recurrence would march left-to-right: h1, then h2, then h3. Mamba uses a parallel scan so many of those combines happen at the same time.

Why 20 rounds?

1024 = 210. The up-sweep takes 10 tree levels to build G[1:1024]. The down-sweep takes 10 tree levels to distribute the correct left context to every token. So the dependency depth is about 10 + 10 = 20 rounds, instead of 1024 left-to-right waits.

Does that mean only 20 computations?

No. The total arithmetic does not become 20 operations. What shrinks is the critical path: the number of steps that must wait for previous steps.

Sequential recurrence

h1 waits for h0
h2 waits for h1
h3 waits for h2
...
h1024 waits for h1023
work: about 1024 state updates
dependency depth: 1024 rounds

Parallel scan

round 1: 512 pair combines at once
round 2: 256 chunk combines at once
...
round 10: 1 whole-sequence combine
rounds 11-20: distribute prefixes
work: still O(1024), with scan overhead
dependency depth: about 20 rounds

So the scan can even do more raw combine bookkeeping than a plain left-to-right loop. It wins because GPUs hate long dependency chains and love many independent operations at once.

Prefill comparison: Mamba with and without scan

This matters for prefill: processing the whole prompt before generation begins. During one-token decode, Mamba just updates the state once, so scan is not the main trick there. During prefill, scan lets the prompt tokens run as a parallel batch.

Prefill method for N=1024 Raw recurrence work Sequential waits Wall-clock intuition
No parallel scan ~1024 updates 1024 Must march through tokens one by one along the sequence.
With parallel scan O(1024) combines ~20 Many combines happen simultaneously; the waiting chain is tree height.

Useful speed intuition

If the recurrent dependency were the whole bottleneck and the GPU had enough parallel work, the dependency-depth improvement for 1024 tokens is roughly 1024 / 20 ≈ 51×. Real end-to-end prefill speedup is smaller because projections, convolutions, memory movement, kernel overhead, and hardware limits also matter.

Ground-level mental model: Mamba cannot use one fixed convolution kernel because every token creates its own at and bt. But each token still creates a composable affine function. Parallel scan turns "do N recurrence steps one by one" into "compose many small functions in a tree, then read out every prefix."

Chapter 9

What Gets Cached — And Why Mamba Never Grows

During inference, every model must remember something about the tokens it has already seen. The question is: how much? This is where Mamba fundamentally differs from Transformers.

The Transformer Problem: KV Cache Grows Forever

In a Transformer, during autoregressive generation, every new token needs to attend to all previous tokens. To avoid recomputing the Keys and Values of past tokens, they are stored in a KV cache.

Transformer KV Cache — Per Layer

Stored: K vectors + V vectors for every token seen so far Shape: 2 × N × d At N=100K: 2 × 100,000 × 2,048 × 2 bytes = 781 MB per layer

The KV cache grows linearly with sequence length. At long contexts, it can exceed GPU memory.

Mamba's State: Fixed Size, No Matter How Long the Sequence

Mamba doesn't have a KV cache. Instead, it maintains a fixed-size hidden state that gets updated with each token — not appended to. After processing a token, the old state is gone; only the updated state remains. Here's exactly what gets stored:

Mamba Inference State — Per Layer

1. SSM Hidden State
h ∈ ℝE × n

Each of the E expanded dimensions maintains its own n-dimensional state vector. This state summarizes all past tokens — like a compressed memory.

Toy: E=4, n=2 → 8 numbers
Real: E=4096, n=16 → 65,536 numbers
2. Conv1D Buffer
buf ∈ ℝE × (k-1)

The Conv1D needs to see the previous k-1 tokens' x' values (where k is the conv kernel size, typically 4). This is a tiny circular buffer.

Toy: E=4, k=2 → 4 numbers
Real: E=4096, k=4 → 12,288 numbers
Total state per layer: E × n + E × (k − 1)
Toy: 8 + 4 = 12 numbers
Real: 65,536 + 12,288 = 77,824 numbers
In FP16: 77,824 × 2 bytes = 156 KB per layer
The crucial point: This state is FIXED. Token 1 and token 1,000,000 use the exact same amount of state memory. The state doesn't grow — it gets updated in place. Old information is compressed into the state via the recurrence, not stored verbatim.

Why E × n? Understanding the State Shape

You might wonder: why is the state E × n, not d × d or N × d? Let's trace where each dimension comes from:

E (expanded dim) The input x (dim d) is projected UP to dimension E = 2d. The SSM runs E independent copies of the recurrence — one per expanded dimension. Each copy has its own state. n (state dim) Each independent SSM copy maintains an n-dimensional state vector. n is typically 16 in real Mamba. This is the "memory capacity" per channel — how many different things each channel can remember simultaneously.

During decode (generating one new token), every operation in the Mamba block runs once. Let's count the FLOPs:

WITH REAL MAMBA VALUES (d=2048, E=4096, n=16, k=4):
Linear projections: 6 × 4096 × 2048 = 50.3M FLOPs
SSM operations: 10 × 4096 × 16 = 655K FLOPs
Total: ≈ 51M FLOPs per token per layer
Notice: The SSM recurrence itself (the h = Ā·h + B̄·x step) costs only 4En FLOPs. The dominant cost is the linear projections (6Ed). The state update is cheap — it's the projections in and out that dominate. And critically: none of these depend on N (the sequence length). Token 1 costs exactly the same as token 1,000,000.

Why There's No N² Anywhere

You might have expected O(N²) somewhere — after all, Transformers have it. But Mamba has no attention mechanism, and therefore no N × N similarity matrix. Here's what each model computes during decode:

Transformer Decode

New query q attends to all N cached keys:
scores = q · KT → O(Nd) per token
attn = softmax(scores) · V → O(Nd)

Cost grows as N increases because the query must "look at" every past key.

Mamba Decode

New token updates the state in place:
h = Ā × h + B̄ × x → O(En)
y = C · h → O(En)

Cost is always the same. The state h is size E×n regardless of how many tokens preceded it.

The trade-off: Mamba's fixed state means it compresses past information rather than storing it verbatim. A Transformer with full attention can recall any detail from token 1 at token 100,000 (at the cost of a massive KV cache). Mamba's state is a lossy summary — old information fades exponentially (controlled by Ā). This is why hybrid architectures (Mamba + a few attention layers) are emerging as the practical sweet spot.

Key Insight

The Transformer's KV cache is lossless — it stores every past token's exact K and V. Mamba's state is lossy — it compresses all past tokens into a fixed-size vector via the recurrence ht = Āt × ht-1 + B̄t × xt. The selectivity mechanism (Δ) ensures that important tokens are remembered strongly and noise tokens fade quickly. This is why 156 KB can replace 781 MB — because most of those 781 MB was storing information about tokens like "the", "of", "is" that the model didn't need anyway.

The Complete Picture

Key Takeaways

1
Mamba replaces both Attention and FFN with a single block.

Half the parameters, same expressiveness. The selective SSM handles cross-token mixing (what Attention did) while the gating handles per-token processing (what FFN did).

2
The selective SSM computes B, C, and Δ FROM the input — content-dependent processing.

Unlike classical SSMs (S4) where these are fixed, Mamba makes them input-dependent. Each token gets its own dynamics.

3
Δ (delta) controls the forget/write balance — the core of selectivity.

Large Δ = erase old state, write new strongly. Small Δ = preserve state, barely write. The model learns when to remember and when to forget.

4
Conv1D provides local context, SSM provides long-range context, gating provides output control.

Three complementary mechanisms working together in a single block.

5
During inference: O(1) per token, constant memory. No KV cache!

The hidden state h is a fixed-size vector (N elements per channel). Unlike Transformers where the KV cache grows linearly with sequence length, Mamba's memory is constant regardless of how many tokens have been processed.
