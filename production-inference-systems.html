Part 1

Cold starts are weight movement problems.

A cold start is not just "a pod is slow." For LLM inference it usually means the system must reserve a GPU, create CUDA context, load tens or hundreds of GB of weights, initialize kernels, allocate KV cache blocks, warm the tokenizer path, and only then accept traffic.

Cold path

request arrives
no warm replica has capacity
scheduler asks cluster for GPU
container starts
model weights load to HBM
engine builds CUDA graph / kernels
KV block pool allocated
first request finally runs

Warm path

request arrives
router finds warm replica
prefix cache checked
continuous batch admits request
prefill starts immediately
tokens stream
Rule: do not autoscale from zero for interactive LLMs unless the SLO is loose. Keep a warm pool sized for the expected burst, and scale the warm pool using queue depth, active tokens, and GPU memory pressure rather than CPU utilization.

Part 2

Cache-aware routing beats blind load balancing.

Traditional load balancing asks: "Which server is least loaded?" LLM routing must ask a second question: "Which server already has useful KV state?" If two requests share a long system prompt, chat history, or document prefix, routing them to the same cache domain can save prefill work.

Step-by-step routing trace

R1: tenant=finance, prefix_hash=abc, prompt=9000 tokens
router sees no cache hit
send to prefill replica P4
P4 computes prompt KV and publishes prefix_hash=abc

R2: tenant=finance, prefix_hash=abc, prompt=9200 tokens
least-loaded replica is P1
but P4 has a 9000-token prefix hit
router sends R2 to P4 if queue penalty < saved prefill time
Decision formula: choose the cache-hit replica if queue_delay_hit + residual_prefill is lower than queue_delay_empty + full_prefill. This ties directly to prefix caching, RadixAttention, and PagedAttention from earlier lectures.

Part 3

Canary deployments for models are not web deploys.

A normal backend canary watches error rate and latency. An LLM canary must also watch output quality, refusal rate, structured-output validity, token length drift, cost per request, cache hit rate, and safety filter triggers.

1. Shadow

Send production inputs to the candidate model but do not return its outputs. Compare latency, schema validity, safety flags, and eval score offline.

2. Canary

Route 1 percent of low-risk traffic. Hold back high-risk tenants, long-context requests, and expensive workflows until basic signals are clean.

3. Ramp

Increase to 5, 25, 50, and 100 percent only if P99, cost, quality, and safety stay within guard bands.

promotion_gate(candidate):
  require eval_score >= baseline - tolerance
  require json_validity >= baseline
  require p99_ttft <= baseline * 1.10
  require avg_output_tokens <= baseline * 1.15
  require safety_flag_rate <= baseline + guard_band
  require rollback_plan == tested
Common incident: a prompt or model update increases average output length. Quality may look better in demos, but cost/request and decode occupancy explode. This is why output-token distribution is a production metric.
Part 4

Guardrails live before and after generation.

Guardrails are not a single classifier. They are a pipeline around inference. The pre-generation layer rejects or rewrites unsafe inputs. The decoding layer enforces structure. The post-generation layer filters policy violations, PII, malformed JSON, and business-rule failures.

Input side

authtenant policyPII detectionprompt injection checksrate limits

Output side

schema validationsafety classifiercitation checktool arg validationrepair or fallback

Latency trade-off: every guardrail adds work. Put cheap deterministic checks first, route risky requests to stronger models or stricter policies, and reserve expensive judge models for sampled audit or high-risk flows.

User expectationFirst token quickly, stream smoothlyFinish eventually, maximize throughput

FailuresFallback or graceful error nowRetry, checkpoint, resume

The production answer

Do not send batch jobs through the same hot online queue unless they are explicitly low-priority and preemptible. Batch traffic can fill idle GPUs, but it must yield to online decode or it will destroy tail latency.
