Why convolution isn’t that expensive: a musical journey.

A microphone records sound as air pressure over time: low pressure, high pressure, low pressure again, thousands of times per second. To add reverb, we ask a practical question: how should each pressure sample echo into the future?

1. The sound problem

Reverb is the room answering the song after the song speaks.

Imagine one clean violin note in a totally dry studio. Now move the same note into a concert hall. The direct note reaches you first; then quieter copies bounce from walls, ceiling, seats, and the back of the room.

That echo pattern is called an impulse response: if the room hears one tiny click, how does the room ring afterward? Reverb means mixing the song with that room response.

The page synthesizes the note and the reverb in your browser. No audio file is needed: the dry note is a small harmonic tone, and the room is a decaying echo pattern.

2. The slow reverb calculation

Direct convolution asks every output sample to look backward through time.

If the room keeps echoing for N samples, then every output sample has to ask: how much of the current note, the previous note, the note before that, and so on, should be added here?

y[t] = Σ song[t - j] · room[j]

This is convolution. The slow version is N output moments times N possible echo delays, which has the square shape N².

Every row is one output time.

Each colored tile is one past sample being mixed into one new reverb sample.

3. The fast route

FFT says: combine song and room by frequency, then come back to time.

A song is pressure over time. The room response is also a tiny signal over time. FFT converts both into frequency coefficients. Then reverb becomes simple: multiply matching frequency bins, then inverse FFT back to pressure samples.

Tiny correction: this is not one big dot product. It is point-by-point multiplication: song frequency 0 times room frequency 0, song frequency 1 times room frequency 1, and so on.

4. Toy version of the frequency knobs

Before the whole song, use eight numbers.

Now we shrink the sound idea down to a tiny sequence: [3, 5, 3, 1, 3, 5, 3, 1]. This toy wave lets us see exactly where the repeated work is hiding.

Main idea

Direct DFT computes each frequency from scratch. FFT notices that pairs such as X2 and X6 share the same even-position work and a flipped version of the same odd-position work.

shared work per pair × log₂(N) levels

That repeated sharing is the visual reason the work becomes N log N.

The time sequence is [3, 5, 3, 1, 3, 5, 3, 1]. The frequency question is: what are the eight coefficients X0 through X7? Once we have them, the inverse DFT adds eight basis waves back together at each time step.

xn = (1/8) Σk=07 Xk W8-kn

The basis waves get faster as k increases. In this clean example, only X0, X2, and X6 are active. The other wave knobs are zero, so their waves are shown as silent.

Add the active pieces at every n.

The flat layer contributes 3 everywhere. The X2/X6 pair contributes the real sine wiggle [0, 2, 0, -2, 0, 2, 0, -2]. The sum reconstructs the original sequence.

5. The slow way to find coefficients

Direct DFT computes every coefficient against every time value.

To find X0 through X7 directly, each frequency row scans all eight time values. Each colored tile is one multiply-and-add interaction in the DFT sum.

Xk = Σn=07 xn W8kn

Eight coefficient rows times eight input columns gives 64 interactions. In general: N rows times N columns gives N².

6. Why reuse is possible

For X2 and X6, the angles repeat with one clean flip.

For each coefficient, every time value gets a direction. The value gives the arrow length; the coefficient decides the angle pattern.

For X2 The angles go 0°, 90°, 180°, 270°, then the same four directions repeat.
For X6 The even positions keep the same angles as X2. The odd positions flip vertically: 90° becomes 270°, and 270° becomes 90°.
The key reuse X2 and X6 do not need two totally separate scans. Split into even and odd groups, reuse those summaries, then flip the odd summary to get the paired coefficient.

Now find X2 and X6 by adding eight colored vectors.

Each time value becomes one vector. The value sets the arrow length; the angle comes from the coefficient we are calculating. We add the arrows as vectors, not as plain magnitudes.

7. Why this becomes N log N

Reuse happens in layers: 8 → 4 → 2 → 1.

N

Work per layer

At one layer, every value belongs to one small even/odd reuse group.

log N

Number of layers

Halving the problem gives 8 → 4 → 2 → 1, which is 3 layers for N = 8.

N values per layer × log₂(N) layers = N log N
