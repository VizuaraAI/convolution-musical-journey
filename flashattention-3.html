First principles

Horace’s useful lens: compute, memory, overhead.

A GPU can be limited by different things. If data movement is the bottleneck, adding more FLOPs does not help. If matmul is the bottleneck, you want Tensor Cores. If small operations or scheduling leave gaps, the GPU is not truly running at peak.

FA1 attacked memory traffic. FA2 attacked work partitioning. FA3 attacks the remaining gaps inside the kernel, especially on Hopper where matmul is extremely fast.

Hopper tools

FA3 uses hardware features that FA2 did not fully exploit.

Hopper gives the kernel new machinery. The point is not just “faster hardware”; the point is that the hardware is asynchronous, so the algorithm can overlap work that used to wait in line.

The big shift is that memory movement becomes more like a background supply line instead of work that the same compute workers must babysit step by step.

WGMMA

WGMMA means Warpgroup Matrix Multiply-Accumulate. Instead of one warp issuing a smaller Tensor Core operation, a group of warps cooperates on a larger matrix multiply instruction.

Before: smaller warp-level MMA instructions.
Hopper: warpgroups issue larger asynchronous WGMMA work.
FA3 benefit: more Tensor Core throughput if scheduling feeds it well.

TMA

Tensor Memory Accelerator is a Hopper copy engine. Give it a tile shape and memory layout, and it moves the tile into shared memory with less per-thread address work.

Before: many threads calculate addresses and issue copies.
Hopper: TMA handles multidimensional tile copies.
Bypass registers: data goes HBM → shared memory, not HBM → registers → shared memory.
Why this matters: fewer registers are occupied by temporary copy data, so register pressure falls.
Also: CUDA cores do less address arithmetic for rectangular tiles.
FA3 benefit: compute can continue while the next tile arrives.

FP8

FP8 stores numbers in 8 bits instead of 16. Hopper Tensor Cores can run FP8 matmuls faster, but attention must manage scale and outliers carefully.

Good: less data and faster FP8 Tensor Core matmul.
Risk: outlier dimensions distort quantization scale.
FA3 fix: mix Q/K so outlier energy is spread before quantization.
Asynchrony

The main FA3 idea: hide one kind of work behind another.

If matmul, memory copies, and softmax happen in separate chunks, some hardware units sit idle. FA3 pipelines them: TMA loads future tiles while WGMMA computes current tiles, and softmax runs while another matmul is already underway.

FA2-like timeline work happens, then the next thing starts

Low precision

FP8 is fast, but outliers make it fragile.

FP8 gives much higher Tensor Core throughput, but activations can contain rare large values. If one feature dimension has a giant outlier, quantization has to cover that giant range, and many normal values become coarse.

FA3 uses incoherent processing: apply a random-sign Hadamard transform to Q and K to spread out outlier energy before FP8 quantization.

Final comparison

FA2 gave more work to the GPU. FA3 removes waiting inside that work.

The story is cumulative. FA3 does not replace the FA1/FA2 insights. It builds on them and makes the attention kernel match Hopper’s hardware more closely.

FA1

Avoid materializing the N × N attention matrix in HBM. Use tiling and online softmax.

FA2

Improve work partitioning and parallelism so more thread blocks and warps stay useful.

FA3

Exploit Hopper: WGMMA, TMA, overlapping matmul/softmax, and FP8 with outlier-aware mixing.

FA3 mental model: the best kernel is not just fast work. It is fast work with fewer empty slots between work.
