OpenVINO GenAI concept, explained visually

KV cache eviction is selective memory pressure.

Instead of keeping every old token forever, the runtime protects the beginning, protects the latest tokens, and lets attention scores decide which middle blocks still deserve memory.

One sequence during generation after prefill

The cache is not deleted token by token. OpenVINO's algorithm works at block granularity, so full blocks in the evictable region are the candidates.

1. Mental model

The cache is split into three logical areas.

The model first processes the prompt normally. During generation, the algorithm imposes a limit on how much KV cache a sequence may occupy.

No eviction happens during prefill, so very long prompts can still create a large temporary cache before the generation-time limit takes over.
Start area Instructions, role setup, early anchors. Never evicted.
Evictable area Older middle context. Blocks compete using accumulated attention scores.
Recent area Fresh tokens. Protected while they are recent, then they age into the middle.

Prompt fills the cache

The prefill phase runs with the full prompt visible. Eviction is not the tool for prefill speed.

Generation begins

New tokens enter the recent area. Older tokens drift toward the evictable area.

Scores accumulate

Attention paid to retained tokens is aggregated across layers and generation steps.

Blocks are removed

When the limit is exceeded, low-value blocks in the middle are evicted.

2. Importance scores

Attention becomes a memory score.

If future tokens keep attending to a block, that block is probably useful. If a block gets little attention, it becomes a better eviction candidate.

This follows the H2O-style intuition: heavy-hitter tokens should stay because the model repeatedly looks back at them.

3. Interactive eviction

Choose a policy and watch the middle change.

The protected start and recent regions stay stable. The policy only changes which evictable blocks survive.

A smaller cache limit means more stable latency and lower memory use, but quality can drop if a removed block later becomes important.

4. Optional refinements

Some modes protect diversity, not just popularity.

Pure attention score keeps the most looked-at blocks. Adaptive R-KV and KVCrush add a second idea: keep representative blocks so the remaining context is not redundant.

OpenVINO recommends Adaptive R-KV for reasoning-style usage because diversity can help avoid repetitive or redundant reasoning traces.

Adaptive R-KV

First preserve a configurable share of attention mass. Then fill the rest of the budget with blocks that are dissimilar to what was already kept.

KVCrush

Build binary indicators from importance scores, compare block patterns to an anchor, and keep representative blocks from the evictable area.

5. Cache rotation

RoPE dislikes holes in position space.

Eviction removes old blocks, but positional embeddings still remember where those blocks used to be. Cache rotation tries to re-rotate retained blocks so their effective positions become continuous again.

Rotation is optional and model-dependent. It targets regular, linear LLaMA-like RoPE layouts and can degrade accuracy on other RoPE schemes.

After eviction

Some blocks are gone, leaving gaps in the original position rhythm.

After rotation

Retained blocks are adjusted so the remaining cache is closer to continuous.

6. Practical tuning

The knobs are accuracy versus memory.

Larger protected areas preserve more context. Smaller limits reduce memory and keep token latency steadier during long generations.

Use task-specific evals. A chat summary may tolerate eviction; coding agents and deep research often need old constraints, file paths, and tool outputs.
Knob Plain meaning What to watch
start_size How much of the beginning is always retained. System prompts, task setup, and early constraints.
recent_size How much newest context is protected. Local coherence and immediate instruction following.
max_cache_size Total cache budget after generation-time eviction starts. Memory, concurrency, and long generation stability.
aggregation_mode How attention scores are accumulated and interpreted. Reasoning quality, redundancy, and recall of older details.
apply_rotation Whether retained RoPE blocks are re-rotated after eviction. Only enable after testing on the model's RoPE scheme.
