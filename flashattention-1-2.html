The key idea

FA1 found the memory trick. FA2 found more parallel work.

Both versions compute exact attention. They tile Q, K, and V into on-chip memory and use online softmax so the full attention matrix never needs to be stored. The difference is how the GPU workers are assigned.

O = softmax(QKᵀ / √d) V    // same result in FA1 and FA2
The clean teaching version: FA1 is excellent when batch × heads gives the GPU many independent jobs. FA2 adds parallelism inside a single head by splitting along sequence/query blocks.

Loop order

Look at who owns the output rows.

In FA1, a useful mental model is: load a K/V tile, then visit Q tiles. That gives reuse of K/V, but the parallel work is naturally organized over batch and heads. In FA2 forward pass, a worker owns a block of Q rows and streams across all K/V blocks, so different Q blocks can run at the same time.

Important: this is not because K blocks are impossible to run in parallel. It is because splitting one query row across K blocks creates partial softmax pieces that must be merged before the final output row is known.

FlashAttention-1: enough jobs only when B × H is large

Training often has many batches and heads, so FA1 can fill the GPU with independent attention problems.

FlashAttention-2: split one head across Q blocks

Even with one batch and a few heads, a long sequence contains many Q blocks that can become independent GPU jobs.

parallel axis: batch × head × Q-block
outer ownership: Q rows / output rows
inner loop: stream through K/V blocks
The confusing part

Why not run K0, K1, K2, K3 in parallel?

For one query row, attention is a softmax over all keys. If four workers each handle a different K block, they do not produce four independent outputs. They produce four partial pieces of the same output row. Those pieces need a max/sum/output merge.

Splitting across K blocks creates a reduction problem

The same Q row owns one final output vector Oᵢ. Every K/V block contributes to that same Oᵢ, and softmax normalization couples all K blocks together.

K-block parallelism is possible, but it needs an extra combine step. That style appears in specialized long-context decode kernels, where Q length may be one token and splitting across Q rows gives no parallelism. FA2's clean forward-pass improvement is to split across Q blocks.
Small batch, long context

Inference exposes the weakness of only using batch × head parallelism.

During prefill, inference may process a long prompt with batch size 1. If the kernel can only create one job per head, the GPU can be under-occupied. FA2 creates more jobs by splitting the sequence dimension, so one long prompt can occupy many thread blocks.

This is the key story to show visually: FA2 does not reduce the N² attention math. It gives the GPU more simultaneous pieces of that math to execute.

Why more peak FLOPs?

Tensor cores like big, steady matrix work. FA2 removes more of the waiting around it.

FA1 already avoided the giant HBM writes. But compared with GEMM, it still had overhead: scalar softmax work, synchronization, and shared-memory movement between warps. FA2 improves the work partitioning so more time is spent in the high-throughput matmul parts.

1. More blocks One long sequence can create many independent Q-block jobs.
2. Less waiting Higher occupancy means more SMs have useful work at the same time.
3. Better warp split FA2 reduces communication through shared memory inside a thread block.
FA2 speedup = better parallelism + fewer non-matmul FLOPs + less shared-memory traffic
Training vs inference

Does FA1 vs FA2 change between pre-training and inference?

The attention formula does not change. What changes is the shape of the workload. That shape decides whether FA2's extra sequence parallelism is especially valuable.

Pre-training

Usually many batches and heads. FA1 already has lots of independent attention jobs, so it works well. FA2 still improves throughput.

Inference prefill

Often batch is small, but the prompt is long. This is the clean case where FA2's Q-block sequence parallelism helps keep the GPU busy.

Inference decode

Usually q length is 1 token and K/V comes from cache. Splitting across Q rows is less useful; specialized decode kernels split work over the long K/V cache.

gist

FA2 is not a different attention layer. It is a better GPU implementation of the FlashAttention idea: same exact output, better work scheduling. Its sequence parallelism is most important when batch × heads alone is too small to fill the GPU, which is common in long-context inference prefill.
